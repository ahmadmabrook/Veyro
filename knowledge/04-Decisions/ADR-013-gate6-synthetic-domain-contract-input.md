# ADR-013: Gate-6 synthetic domain-contract input and fail-closed partial boundary

## Governing limit

TSD §24.1 requires a CI lint comparing six normalized dimensions across all 57 §10 domains. Identical command inventories and reused `RB-<DOMAIN>` IDs fail unless an explicit shared-contract exception is approved. MOD-001 `IMPLEMENTATION.md` §4 and `SCENARIOS.md` SCN-014/015/131 additionally require synthetic positive/negative and exact exception behavior. At this ADR's initial adoption, the live `--gate domain-uniqueness` was `ERROR/GATE_NOT_IMPLEMENTED` (exit 2). Later local partial increments do not make the live gate PASS. The original Decision 1–4 below governed **only the first synthetic P1/P2 increment**; the dated D4 addendum below governs the additional prose-input fields, without satisfying the complete gate or any scenario.

The architecture decisions are recorded in `knowledge/03-Modules/MOD-001/evidence/implementation/R04-GATE6-SOURCE-NORMALIZATION-LEAD-DECISION-2026-10-09.md` (D1-D5), qualified by `MR-MOD-001-20261009-005.json`, and `R04-GATE6-RESERVATION-ENTITY-LEAD-DECISION-2026-10-09.md`, qualified by `MR-MOD-001-20261009-006.json`. The latter resolves COM-01 `EntitlementReservation` as distinct from `MemberEntitlementGrant` using TSD §10.12, §15.2 and Appendix E.1. It does **not** create the 57-domain inventory.

## Decision

1. **Synthetic input only.** The bounded validator increment reads one disposable machine-readable domain-contract input with explicit `domain_id`, `entities`, `commands`, `published_events`, `runbook_ids`, `dependencies`, `slo_signals`, and `failure_terms`. Values carry a source pointer or an explicit `synthetic` provenance marker. The validator does not parse TSD prose or invent missing values. A malformed, absent, duplicate, or provenance-less required input is ERROR/exit 2. No real-domain registry is created by this ADR.
2. **Deterministic P1/P2 comparisons.** Normalize only Pandoc escapes, whitespace, comma-list boundaries and terminal punctuation; compare identifiers case-sensitively. Command inventories compare as unordered sets of exact commands, so byte-order differences do not conceal an identical inventory. Reuse of the same exact runbook ID or an identical command inventory across two distinct domains is `DOMAIN_CONTRACT_COLLISION`, FAIL/exit 1, naming both domains and the artifact. No stemming, synonyms, fuzzy matching, or generic-word exclusions.
3. **Exact pair-specific exception.** An exception identifies one unordered domain pair, one dimension (`command-inventory` or `runbook-id` for this increment), the exact colliding artifact (runbook ID or digest of the sorted command set), an exception ID, and an approval reference resolving to exactly one affirmative approval row. It clears **only** that collision and cites the exception ID; it cannot clear another pair, artifact, or dimension. Malformed, duplicate, stale, or unresolved approval is ERROR/exit 2, never an implicit waiver. SCN-131's positive fixture uses disposable synthetic copies of the exception and approval inputs; a synthetic row is test data, **not** live owner approval. The live exception register is not populated here.
4. **Full-gate result remains ERROR.** The entity, published-event, SLI/SLO-signal, and failure-vocabulary dimensions are not implemented in this increment. After any P1/P2 checks, the aggregate gate must return ERROR/`DOMAIN_DIMENSION_NOT_IMPLEMENTED`/exit 2 unless a P1/P2 collision already requires FAIL/exit 1. A component-level P1/P2 success, including an exception-resolved success, is **not** a full gate PASS and cannot promote SCN-014/015/131. Later complete enforcement, CI-blocking wiring, shared scenario execution, risk-required independent assurance, and individual dispositions remain mandatory.

## Scope and source accuracy

The TSD source facts for command inventories and runbook IDs support this synthetic comparison without choosing real entity-set or free-form vocabulary semantics. The accepted lead decision's broader T1/T2/T3 real-domain reconciliation-entry mechanism is **OPTIONAL now** and is not implemented or registered by this ADR. COM-01's source naming decision is retained as evidence, not converted into a live canonical registry. PLT-03 and other real-domain extraction inconsistencies remain ERROR until separately reconciled. This is a technical lint-input method, not a change to product entities, ownership, approval rights, baseline text, or scope; no DC-16 owner approval is inferred or required for this bounded method.

No code, tests, CI, review counter, scenario state, gate verdict, or module certification was changed by the initial ADR. Its original next action was the synthetic P1/P2 component; subsequent local increments and the new D4 input decision are recorded below, not retroactively claimed complete. ## D4 addendum — observed prose as separate synthetic input (2026-10-09)

**Qualified decision and scope.** `veyro-lead`/Opus 5.5 decided P-1 through P-6 in `knowledge/03-Modules/MOD-001/evidence/implementation/R04-GATE6-D4-PROSE-INPUT-LEAD-DECISION-2026-10-09.md`; independent runtime proof is `MR-MOD-001-20261009-007.json` (17/17 turns). This addendum transcribes that technical input-contract decision; it is not a second architecture judgment, code review, scenario disposition, or owner approval. The initial seven-field contract above is historical for the first P1/P2 increment. For the next synthetic input increment, the **exact** per-domain fields are `domain_id`, `entities`, `commands`, `published_events`, `runbook_ids`, `dependencies`, `slo_signals`, `failure_terms`, `slo_text`, and `failure_text`.

1. **Separate observation from ownership (P-1/P-2).** `slo_signals` and `failure_terms` remain owned-term declarations, never the prose being scanned. `slo_text` contains observed SLI/SLO prose passages; `failure_text` contains observed failure/degraded-behavior prose passages. Neither prose field grants ownership. Each new field has the existing `{"value": ["<passage>", ...], "provenance": "synthetic" | "<source pointer>"}` shape with per-field provenance. MOD-001 uses `synthetic` only. The validator treats any source pointer as opaque metadata and never opens or parses the TSD/mirror to populate the fields. The original seven fields retain their current shape and may-empty rule.
2. **Fail-closed input (P-3/P-4).** Both prose fields are required for **every** domain, and each `value` list must contain at least one nonblank string. Missing/symlinked/unreadable document, missing prose field, empty passage list, wrong field/object/list/element/provenance shape, duplicate passage under the existing exact duplicate rule, or unknown extra field is `DOMAIN_UNIQUENESS_GATE_INPUT_INVALID`, ERROR/exit 2 for the entire document before any comparison. A seven-field document is invalid after this input-contract increment; there is no optional/partial fallback and no load-time passage rewriting. Existing synthetic fixtures must migrate in the same later code change so P1/P2 controls are preserved.
3. **D2/D4 matching, no new waiver (P-5).** Match prose at comparison time using the qualified D2 casefold, separator/CamelCase and contiguous whole-phrase rules, without stemming or fuzzy inference. D4(a) compares each owned `slo_signals` term to the same domain's `slo_text`, and each `failure_terms` term to its `failure_text`, except when the **declaration field** carries `synthetic` provenance. D4(b) scans every `slo_text` and `failure_text` passage against **all other domains'** declared `slo_signals ∪ failure_terms`. A foreign hit fails `DOMAIN_CONTRACT_COLLISION` unless the scanned domain owns the term itself or explicitly lists the declaring domain in `dependencies`; an absent dependency domain contributes no terms and exempts nothing. Report the scanned domain, declaring domain, matched term, prose field and corresponding SLI/SLO or failure-vocabulary dimension. The D5 pair-specific exception register does **not** waive either D4 dimension.
4. **No premature PASS (P-6).** Merely accepting the two fields leaves `DOMAIN_DIMENSION_NOT_IMPLEMENTED`/ERROR while D4 comparisons remain unimplemented. No real 57-domain document exists at the default path, so the live gate remains ERROR regardless of synthetic fixture results. A future synthetic positive result is fixture-level evidence only; it neither certifies the live gate nor promotes SCN-014/015/131 or MOD-001.

**Explicit limits.** D4(a)'s synthetic declaration exemption makes that anti-invention branch vacuous in MOD-001 synthetic fixtures; no fabricated source pointer is authorized to manufacture a positive proof. If two domains co-declare a term, D4(b) treats it as locally owned; no duplicate-ownership fail predicate has been decided, so the foreign-signal fixture must not co-declare its foreign term. Undeclared or synonymous foreign wording remains outside the declared-term mechanism. A synthetic-provenance document placed at the default live path is a pre-existing cross-field gap, not resolved by this prose-only decision or asserted safe. True real-domain term ownership, prose pointers and source fidelity require later owning-module/approved-authority work. Per-field rather than per-element provenance is the current validator shape and is disclosed. These limits do not authorize a live registry, exception waiver, owner decision by inference, or a scenario PASS.

**Next bounded action.** Under the sole writer lease, implement only the two prose fields, nonempty fail-closed input rule, fixture migration, and D4 comparisons with focused synthetic denial/positive controls; deterministic verification and the separate governed artifact/risk-required assurance boundary follow. Four other comparison dimensions have local evidence only. Aggregate gate ERROR, SCN-014/015/131 NOT EXECUTED, gate-6 review/remediation 0/0, MOD-001 exit 0/8, R04 gate-2 F01–F14 14/14 CLOSED.
