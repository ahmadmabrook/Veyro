This proves the runner fails closed locally. This negative check does **not** verify the actual source documents against a trusted CI pin; the real mission pin lives outside the repository.

### Run / deploy / rollback (local only; "staging" = local staging profile, NOT cloud staging)
- Tests/lint: `cd backend && python -m pip install -r requirements-dev.txt && python -m ruff check . && python -m mypy && python -m unittest discover -s tests -t . -v`
- Build (once per release): `bash infra/scripts/build.sh [release-tag]` tags `veyro-api:<tag>` from `backend/`; default tag is the 12-char git SHA (requires clean `backend/`). Release tags are immutable: build refuses an existing tag.
- Deploy + smoke: `bash infra/scripts/deploy.sh <local|development|staging> <release-tag>` uses the existing local image only (no build, no pull; refuses a missing image), serves `127.0.0.1:${VEYRO_PORT:-8000}`, checks the running image ID, and fails unless smoke matches exact env and release. Stop: `VEYRO_TARGET=<t> VEYRO_RELEASE=<tag> docker compose -f infra/compose.yaml down`.
- Rollback: `deploy.sh` the previous known-good tag; it is the already-built image, not a rebuild. Rehearsal: `bash infra/scripts/rollback-rehearsal.sh [target]` builds image A (copy of `backend/`) and image B (copy with an injected `/healthz` defect) from temp contexts under unique tags, asserts different image IDs, deploys A (pass), B (must fail smoke), then A again without rebuild (same image ID, pass); it removes containers, temp dirs and its images, and refuses if the target already has containers.
