## Acceptance criteria
- A real GitHub run of this workflow passes on the exact current commit (PR or push).
- One intentional failure demonstrably fails the run; required-check enforcement must also be proven before acceptance.
- `main` requires this check plus one approving review, and the check is not bypassable.
- Missing external permissions are recorded as BLOCKED, never PASS.
- Safe dev/staging delivery and rollback rehearsal, only where an environment exists.
- Independent Opus review of the critical changes, then final acceptance. No blanket PASS; N/A needs concrete justification.

## Negative check (in the workflow)
With an empty runner home (no pin): `runner.py verify-baseline` must exit 1 with `NOT_PINNED`; `pin-baseline` without `--confirm-index-sha256`, or with a wrong hash, must exit 2 and write no pin. This proves the runner fails closed locally. This negative check does **not** verify the actual source documents against a trusted CI pin; the real mission pin lives outside the repository.
