## Behaviour
| Concern | Implementation |
|---|---|
| Single runner | `flock` on `locks/runner.lock`; a second `run` exits 3. |
| Single repo writer | `flock` on `locks/repo-writer-<hash>.lock`, held for the whole attempt **including post-run verification**. The lock fd is passed into the child (`pass_fds`), so if the runner is SIGKILLed the orphan child still holds the lock; it frees only when the orphan is dead. Lock file records `runner_pid`, `child_pid`, `task_id`. Recovery reaps the orphan (pid + `ps lstart` must match), then the lock is free; if something unreapable still holds it, an event is logged and dispatch waits (no attempt consumed). Dashboard probes the lock passively and shows "runner dead, orphan child alive" when true. |
| Baseline (P1-1) | `PROJECT_INDEX.md` is **not** trusted at runtime. `runner.py pin-baseline` verified the selected source bytes and wrote `baseline-pin.json` (index and source hashes) outside the repo, mode 0400, no-clobber. The real pin was created at 2026-10-15T09:04:16Z and verified. Every runtime check compares index bytes **and** sources to it; missing pin or drift blocks dispatch. |
| Child isolation (P1-2) | Child runs `claude -p --safe-mode --setting-sources= --settings=<per-attempt file outside repo> --permission-mode=dontAsk --permission-prompts=none --strict-mcp-config --disable-slash-commands --tools=<Read,Grep,Glob[,Edit,Write]>`. Write roles get `Edit/Write` allowed only on the task's `allowed_paths`; `Bash`, `WebFetch`, `WebSearch`, `Agent` and `.git` are denied; review roles are read-only. No bypass flags. Env is a whitelist (`PATH HOME USER LOGNAME LANG LC_ALL TMPDIR SHELL TERM`), so `ANTHROPIC_*`/`VEYRO_*` are not inherited. On macOS the child is wrapped in `sandbox-exec` denying file writes to the state dir (queue, commands, pin, state) and `<repo>/.git`. The old user rule `Bash(npx claude-flow*)` lives in user settings, which the child no longer loads. |
| DONE gating (P0-2) | Exit 0 is not enough. A writing task must change at least one repository file, remain in declared scope, satisfy expected changes and any external `verify_cmd`, return `subtype=="success"` with no permission denials, report a verified route, preserve git HEAD, and pass the post-run baseline check. Read-only reviews require a final `OUTCOME: APPROVED`; `CHANGES_REQUESTED` is recorded as BLOCKED, as the live Opus review demonstrated. Evidence is saved in state and `runs/<op>.evidence.json`. |
| Routing (P0-1) | `--model opus` for assurance roles; `--model sonnet` for implementation/test roles. Only actual token fields count; capacity fields are ignored. `canonicalModel` is preferred. **Any** observed wrong-family token use blocks verification; no usage is UNVERIFIED. Both live dispatches reported the intended family (`claude-sonnet-5-5`, `claude-opus-5-5`). |
| Queue durability (P1-4) | `state.json` is saved with the new task *before* the queue file is unlinked; a crash in the window leaves the file for the next runner (re-ingest is idempotent). Both crash orderings are tested. |
| Durable state | tmp+fsync+rename plus **parent-dir fsync**; fsynced append-only `events.jsonl`. Unreadable/wrong-schema state ⇒ runner refuses to start (exit 4), never overwrites. Validation uses explicit raises, not `assert` (works under `-O`). |
| Control / retry / recovery | `pause`/`resume`/`stop` with op ids, applied once; max 3 attempts, backoff 5·2^(n-1) s ≤ 300 s; timeout 3600 s. Baseline mismatch *during* a child kills it and blocks for triage. Heartbeats persist during child and verification work. STOP/SIGTERM during verification kills that command, leaves a durable verification-only checkpoint, and resumes the check without re-dispatching Claude. The verification child inherits the writer lock; crash recovery reaps it. |

## Dashboard (read-only, loopback, polls every 3 s)
Overview tiles; ticking heartbeat and uptime; Kanban columns **NOT STARTED, READY, IN PROGRESS, IN REVIEW, BLOCKED, DONE**; filters by module / phase / status / agent(role); click a card for full task detail (route models and tokens, changed files, verify output, outcome, isolation, recent events); live operations (running task, elapsed, child pid, writer-lock state); module details; baseline pin status; usage; routing evidence; events; dark/light toggle (defaults to OS setting). Mapping is literal: queued ⇒ READY, running ⇒ IN PROGRESS, running-but-in-post-run-verification ⇒ IN REVIEW, blocked **and failed (retries exhausted, tagged FAILED)** ⇒ BLOCKED, done ⇒ DONE. **NOT STARTED is always empty** — there is no backlog/plan source, so it says so rather than inventing cards. Absent data (no phase, no CI, no runner) reads "unavailable". Health is `UNKNOWN` until a runner has actually checked; the former fabricated "Baseline OK" is gone, and a stopped runner's last result is labelled stale. Visually inspected in headless Chrome (light, dark, selected-task view) against a seeded fixture state.

## Operating it
```
R=tools/mission_runner/runner.py
python3 $R pin-baseline                                   # OWNER, once; prints hash to confirm
python3 $R pin-baseline --confirm-index-sha256 <hash>
python3 $R run | dashboard [--port 8766] | status | pause | resume | stop | verify-baseline
python3 $R enqueue --id X --module MOD-000 --role implement --plan-phase P1 \
   --allow src/foo/ --expect src/foo/a.py --verify-cmd '["python3","-m","unittest"]' --prompt-file p.txt
python3 $R enqueue --id R --module MOD-000 --role code-review --prompt-file p.txt   # read-only roles: no --allow/--expect
```
The queue is empty by default; starting the runner starts no work.

## Known limitations / OPEN (read before trusting this)
- Live Claude CLI dispatch is proven for a narrow Sonnet edit, an independent Opus read-only review, and an Opus gatekeeper. This does not prove every role or every permission rule; those remain scoped to later implementing modules.
- **Project hooks and settings are bypassed by design.** `--safe-mode` plus empty `--setting-sources` means the child does not run the project `SessionStart` governance hook, `.claude/settings.json` (currently `bypassPermissions`, `Bash(*)`), CLAUDE.md, skills, MCP or plugins. Children therefore do **not** see the Veyro bootstrap context; each task prompt must carry what it needs. Admin-managed policy settings still apply.
- **Isolation is not a jail.** `sandbox-exec` (deprecated but present) only denies *writes* to the state dir and `.git`; reads, network, and all other paths stay open, and it is macOS-only (elsewhere `isolation.sandbox` records `none`). Permission rules are best-effort; the real control is the external post-run diff. Git-ignored files are invisible to that diff. Tasks that need `Bash` (e.g. a `test` role running suites itself) are not supported; use `verify_cmd`, which the runner executes **unsandboxed** with the owner's rights — `enqueue` is the trust boundary, so only the owner/parent should enqueue.
- A change committed/edited by a human during a task's attempts is attributed to the task (conservative: may cause a false `OUT_OF_SCOPE_CHANGE`).
- There is no off-tier token threshold: any observed wrong-family token use blocks assurance.
- The new LaunchAgents were loaded and the runner read the Desktop repository successfully on this host. This does not prove access on another Mac or account.
- Not built here: Notion mirror, TestSprite, Obsidian vault, `.claude/agents`, `MODEL_ROUTING.md`; CI panel stays "unavailable" until a `ci.json` source exists (MOD-001). `events.jsonl` is not rotated; baseline hashing re-reads ~3 MB per check.
- No baseline pin or live-drill owner action remains pending. The retired plist copies are archived outside LaunchAgents and need no action for safe operation.
