**Source text (supplement, quoted).** EIP ¶750: "When Ready depends on a conditional prerequisite certificate, the edge must satisfy the §18/§22.0 Gated-capability rule: SOFTWARE_ONLY is allowed only with explicit proof that the dependent does not consume the named gated capability." EIP ¶773: "The next module remains LOCKED until the active implementation module is APPROVED, except that a prerequisite holding APPROVED — SOFTWARE COMPLETE, EXTERNAL GATE PENDING may be consumed only through a §18-compliant SOFTWARE_ONLY edge whose evidence proves non-use of every named gated capability still pending."

**Application.** Both prerequisites' `APPROVAL.md` records read "APPROVED — FOUNDATION ONLY, ACTIVATION PENDING OWN EXACT-SHA CI" (MOD-001 conditional in the same way). That is not the ¶773 external-gate status.

**EIP §18 certificate rule (new extract, zero-based ¶1167; the earlier supplement numbering is one higher).** "Every prerequisite is either APPROVED, or has the formal APPROVED — SOFTWARE COMPLETE, EXTERNAL GATE PENDING certificate and this dependency edge is explicitly proven SOFTWARE_ONLY." The MOD-001/MOD-002 certificates read APPROVED — FOUNDATION ONLY; they are not the external-gate certificate and name no pending EXT gate, so SOFTWARE_ONLY proof is **inapplicable and not prescribed**. The open question is whether a foundation-only approval, operative after its activation CI, counts as "APPROVED" for MOD-004's edge. This is an unresolved authorization interpretation and is not decided here. Exact minimal determination needed (independent reviewer or owner/governance record, not the writer): "Does APPROVED — FOUNDATION ONLY for MOD-001 and MOD-002 satisfy EIP §18 ¶1167 'APPROVED' for the MOD-004 dependency edge? Yes / No." Considerations, not a decision: MOD-001 carries owner-deferred items, LF-01 is PROPOSED, and the card says "No special waiver" (¶1954). No product PASS follows from either answer.
