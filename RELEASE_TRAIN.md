# Release Train (GOV-01-R08)

> SYNTHETIC / NON-PUBLIC. This document defines a convention only. No real
> release, customer, store submission, or Production deployment exists or is
> implied. It is validated by `tools/validate_release_lifecycle.py`.

## Release-train cadence

- Synthetic convention: one release train is cut every 4 weeks from `main`,
  named `train-YYYY.NN` (year, sequence number within the year).
- Each train starts as `beta`, is promoted to `GA`, and is later `deprecated`
  (see the per-release record in `tools/validate_release_lifecycle.py`).
- Cadence is a planning convention; no train is published anywhere.

## Maintenance policy

- A train in `GA` receives bug and security fixes for 12 weeks after its GA
  promotion (three subsequent trains).
- A `beta` train receives fixes only until it is promoted to `GA` or
  superseded by the next train.
- A `deprecated` train receives security fixes only, for 4 weeks after
  deprecation, then reaches end-of-support and receives no fixes.
- Applying these windows to real releases is out of scope until a module with
  real releases exists.

## Customer-communication template

Internal/synthetic template only. Never send to a real customer.

```
Subject: [SYNTHETIC] <train-id> is now <beta|GA|deprecated>
Audience: internal test audience (no real customers)
Summary: <one-sentence description of the stage change>
Changes: <changelog entry reference>
Support window: <end-of-support date per the Maintenance policy>
Action required: <none | steps>
```

## Changelog entry format

Generated by `tools/generate_changelog.py` from the committed first-parent
merge/PR history between the prior and current release refs; never
hand-written. One entry per release train:

```
## train-YYYY.NN (<prior-ref>..<current-ref>)

- <PR title> (#<number>)
```

PRs whose conventional-commit type is chore/ci/docs/test/style/build are not
changelog-worthy. A release with no changelog-worthy PR produces no entry.
