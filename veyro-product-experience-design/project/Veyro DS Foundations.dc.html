What is being combined, and why

BASE — 1a LEDGER
Hairline rules instead of shadows, near-zero radius on data, warm paper neutrals, mono numerals, one superfamily across Latin / Arabic / mono. Chosen because it is the only direction whose legibility improves as row count rises — the actual condition of Admin, Front Desk and Console, which are 80% of daily use.
FROM 1b — RADIUS AS AFFORDANCE
Containers and data stay sharp; anything pressable gets 6px. Ledger alone gave touch surfaces no affordance cue. This buys Coach and Member a tactile quality without softening one table — and it is why radius.button is larger than radius.card, which looks wrong in a list and is right on screen.
FROM 1b — ONE ACCENT, SPENT ONCE
Ink blue on action and selection only; semantic colour confined inside status components; adjacency prohibited. Prevents the colourful-status failure §9 warns about, and makes the white-label guardrail in §09 enforceable rather than advisory.
FROM 1c — EDITORIAL SCALE, NOT THE SERIF
Member first-run, milestones, progress reviews and empty moments get type.display and the Spacious density. Same family, different register. The serif itself is rejected: no credible Arabic serif companion exists for UI, so the identity would vanish on half the product.
REJECTED FROM 1c — SHARED HUE
Action and success sharing a green was an accessibility defect, not a stylistic choice. Here they are separated by hue and by token boundary, and the guardrail makes the separation unbreakable by a tenant.
CARRIED FORWARD — SEVERITY FLAG
Step 1 flagged that the attention row's edge-mark and the status badge express one idea twice. Resolved here as a single four-step severity scale (§04) consumed by both: the edge-mark carries the row-level roll-up, the badge always names the specific state.

AI is its own hue, and it is not brand-configurable. Phase 8 surfaced the reason: the AI panel's border was carrying real meaning — “this is interpretation, not confirmed fact” — while inheriting the tenant accent, so under a white-label brand machine inference would have looked like a first-party assertion. ai.600 is a muted indigo, distinct from ink.600 by hue rather than lightness, and locked by guardrail G7. Veyro is accountable for what its AI says, so Veyro owns the colour it says it in. Info is deliberately desaturated slate, not blue. If informational content shared a hue with action, users would learn that blue sometimes means “press me” and sometimes means “read me” — the same defect that disqualified direction 1c. Every semantic hue above is also distinguishable from ink.600 at a glance and passes AA as text on warm.0 and warm.100. The ratios on the chips are white-on-fill — the basis is printed because 7.64 (error.600 as text on warm.0) and 7.70 (white on error.600) are different measurements, and an unlabelled ratio is not a control.

Not “support both everywhere”. Each surface gets an answer with a reason, because dark mode is a permanent maintenance cost and should be paid where it earns something.

DARK IS NOT AN INVERSION
Three rules make it work rather than merely exist. Elevation reverses: in light, higher surfaces get lighter; in dark, higher surfaces get lighter too — so the ramp direction is preserved and hairlines still read. Accent lightens, text on it darkens: ink.600 becomes #7ea6e8 with near-black label, because white on a light blue fails. Semantic hues desaturate and lighten together so error stays error without vibrating against a dark field.

FOCUS RING
2px ink.600 ring plus a 1px warm.0 inner offset, so it reads on both light surfaces and on filled buttons. Never brand-configurable — a tenant cannot make focus invisible. The ring inherits ink.600, so it carries the same 10.13:1 against warm.0 and 9.14:1 against warm.100 as the link token — far above the 3:1 required for non-text.
DISABLED IS NOT LOW-CONTRAST TEXT
Disabled controls use warm.500 on warm.100 at 3.50:1 — exempt from AA as a genuinely inactive control, and always accompanied by a reason on hover or focus. Per Phase 6, disabled is reserved for temporarily unavailable; permanently unauthorised is absent instead.
WHY THIS TABLE EXISTS
Three times in this project a light grey passed review by eye and failed measurement — 2.34:1 in a specimen, 3.17:1 in an audit document that was itself certifying accessibility, and here tertiary on warm.150 at 4.48:1, which the first draft of this very table rounded up to 4.5 and called a pass. Judgement is not a control. Ratios are printed to two decimals for that reason, and the CI allow-list is seeded from unrounded values.

10 · §18

Token architecture — three layers

LAYER 1 · PRIMITIVE
veyro.warm.100
veyro.ink.600
veyro.error.600
Raw values with no opinion. No component may reference these. A lint rule enforces it — this is what makes theming a remap rather than a rewrite.
LAYER 2 · SEMANTIC
color.text.secondary
color.surface.raised
space.4 · radius.button
type.body · elevation.2
What components consume, and the only layer they may. Names describe role, never appearance and never a screen — there is no color.commandCenterBorder.
LAYER 3 · COMPONENT
button.primary.bg
button.primary.bg.pressed
statusBadge.error.fg
table.row.selected.bg
Aliases pointing at Layer 2, existing so a component's surface can be retuned without touching the semantic set. Optional per component; mandatory for anything with more than four states.
THEME AND DENSITY ARE DIMENSIONS, NOT SETS
One token name resolves differently under theme: light | dark and density: compact | default | touch | spacious. There is no color.text.secondary.dark — that naming pattern is how design systems end up with four divergent products.
PLATFORM MAPPING
One JSON source of truth generates CSS custom properties, a SwiftUI Color/Font extension set with Dynamic Type mappings, and Android Compose theme values. Generated, never hand-mirrored — hand-mirroring is how iOS and web drift apart by release three.
CI GATES ON THE TOKEN SET
Three checks block a merge: a component referencing Layer 1; a text/surface pairing absent from the contrast matrix or below threshold; a spacing or radius value outside the scale. All three are failures this project has already made by hand.
