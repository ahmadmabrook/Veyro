The four questions from Phase 6, answered in order, every time. No error state ships without all four and at least one route out.
FIVE KINDS OF EMPTY
First use explains and offers the first action. Filtered names the filters and clears them. Permission says access is missing without implying absence. Success reports what is going well. Error-empty is never dressed as empty — implying no data when the load failed is a lie the user acts on.
THE FOUR PEOPLE FORGET
Partial — some data is stale; say which and how stale. Pending sync — saved locally, not yet server-side, with a count. Conflict — two edits, both shown, user picks; never last-write-wins silently. Stale — the screen was open while the world changed, so it offers a refresh rather than acting on old data.

04 · §57 · §58

Permission and money presentation

ABSENT · THE DEFAULT
A role that can never hold a permission never sees the control. A receptionist's rail has no Finance entry — not a greyed one. Showing people locked doors teaches them the product is bigger and more forbidden than their job.
DISABLED · TEMPORARY ONLY
Reserved for something the user could enable — “refund unavailable until the payment settles”. Always states the condition. A permanently disabled control is a design defect, not an access control.
REQUESTABLE · THE THIRD OPTION
Visible, not permitted, but routable: “Needs Rania's approval — request it.” This is what keeps a 4-month freeze or an over-threshold refund from becoming a phone call, and it is the state most systems omit.
RESTRICTED DATA
Health notes, biometric records and card details render as “restricted” with the reason available — never blank, never partially masked in a way that invites guessing. A blank money cell reads as zero, and zero is a claim.
MONEY · SIX RULES
Code + two decimals always · tabular figures, end-aligned · bidi-isolated in Arabic · sign explicit on anything negative · kind stated (owed, credit, refunded) · aggregates never truncated. Applied identically on screen, receipt, export and PDF.
SAFETY COPY
Medical, injury, allergy and consent content is never brand-styled, never AI-generated without review, and never abbreviated to fit. It gets the same treatment in every tenant because it is the one place white-label flexibility could cause harm.

DS-P0-5 and DS-P1-1 resolved. The governing principle: a native platform owns interaction mechanics, Veyro owns meaning. An iOS sheet uses UIKit dismissal and Dynamic Type; it still says “6 payments failed” with the same severity, the same evidence links and the same confirmation tier.
