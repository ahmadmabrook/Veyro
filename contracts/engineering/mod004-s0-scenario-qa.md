## Contract and non-use boundary

The input is a synthetic command-envelope shape, not a trusted request. It contains an opaque external key, claimed actor and correlation UUIDs, an idempotency UUID, and optional expected-version metadata. The validator may normalize types and reject malformed, missing or extra fields. It may not authenticate the claimed actor, authorize, select or create a tenant, assign a region, mutate state, set tenant context, call an API, or perform file, network, process, SQL or database I/O. A successful parse means **shape valid only**.

**Input form decision: Python `Mapping` objects only.** JSON text is not accepted; a `str`/`bytes` top-level input is a non-mapping rejection. Consequently `json` is not used by the product, and no `object_pairs_hook` exists. (If the reviewed API later accepts JSON text, this packet needs a fresh review and the S0-03 duplicate-key subcase becomes applicable, using `object_pairs_hook` to reject duplicates.)

**Expected-version policy (S0-07).** The TSD ¶1237 / ADR-0002 D6.3 discrepancy remains open and must be stated explicitly in the module docstring or API note; no version requirement is invented for initial provisioning. Tested policy:

- key absent: accepted, normalized to "no version";
- key present with `None`: rejected (present-null is distinct from absent);
- integer `0`: accepted; negative integers rejected;
- documented upper bound (a named module constant, reviewed with the diff): the bound accepted, bound+1 rejected; huge ints (e.g. `10**100`) rejected without resource blow-up;
- `bool` (`True`/`False`), `float` (including `nan`, `inf`, `-inf`, fractional), `str`, containers: rejected.
- NaN/Infinity as JSON literals: NOT APPLICABLE (JSON text not accepted); float `nan`/`inf` objects are still tested.

The exact public function/type names and concrete envelope field spellings are implementation choices to be reviewed with the product diff; this packet does not invent a wire contract. Tests make both accepted and rejected field sets explicit. All values are synthetic.

## Test-design constraints (apply to every row)

- **Runner and CI:** stdlib `unittest` with `subTest` only, not pytest. The runner verifier executes `/opt/homebrew/bin/python3.13 -m unittest backend.tests.test_tenancy_s0` from the repository root; Foundation CI discovers `tests.test_tenancy_s0` with `python -m unittest discover -s tests -t .` from `backend/`. The test module must import the validator in both contexts (for example, `backend.app.tenancy_s0` first and `app.tenancy_s0` on `ImportError`), with no third import path or dynamic import escape. Both command results are required evidence.
- **Determinism:** fixed literal synthetic UUIDs and opaque keys. `uuid.uuid4` is banned in product and tests; no dependence on time, randomness, environment or ordering.
- **Effects:** the product has no file, network, process, environment or database effects. The test file may perform one bounded read of exactly `backend/app/tenancy_s0.py` for the AST import-closure assertion, located from the test file as `Path(__file__).resolve().parents[1] / "app" / "tenancy_s0.py"` in either working directory. It may not read runner.py or any other path, write, create a temp file, or access the environment or a process.
- **Import closure:** because the test cannot import or read runner.py, it embeds a literal positive product-module/name allowlist equal to or stricter than the gate's `S0_PRODUCT_MODULES` / `S0_NAMES`; the bound reviewer compares the two literal lists. It is not a weaker deny-list. `unittest.mock.patch` string targets naming forbidden or escape modules or attributes are forbidden. Tests use only `S0_TEST_MODULES`-allowed names and never inspect `S0_BAD_ATTRS` such as `__traceback__`, `__dict__` or `__class__`. Absence of network/process/DB use is proved by the gate's static allowlist, the sandboxed verifier and bound review, not in-test patches of prohibited modules.
- **Logging:** tests do not import `logging`, `io`, `contextlib` or `sys`; use `self.assertNoLogs()` plus a static/review no-print check.
- **No raw-input leakage:** rejection must not expose raw input in exception `str`, `repr` or `args`, in a chained `__cause__`/`__context__`, or in the repr of a partially built object. Tests inspect only those permitted values; they never inspect `__traceback__`.
